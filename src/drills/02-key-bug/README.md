Після сортування імена в рядках змінюються, а React за ключем `index` вважає, що це той самий компонент на тій самій позиції. Він лише оновлює проп `name`, але не скидає локальний `useState` у `Row`, тож текст нотатки залишається прив’язаним до індексу, а не до людини.

Тому нотатки опиняються біля чужих імен — це не баг input, а наслідок неправильного ключа при повторному використанні екземпляра компонента.

Якщо ключем зробити стабільний `person.id`, React зіставляє кожен `Row` з конкретною людиною: при зміні порядку екземпляр переїжджає разом із нею, і нотатка лишається на своєму місці.

Висновок: у списках з власним станом у дочірніх елементах не використовуйте індекс масиву як `key`, коли порядок або склад списку може змінюватися.
